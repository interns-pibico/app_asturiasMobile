# Sesión 2026-03-13 09:26 — AstuGuía Bridge IA Unificado

## Objetivo

Implementar la bridge FastAPI `/api/guia/chat` que unifica todas las respuestas de AstuGuía (wizard, explorar, chat) pasándolas por el servidor con contexto real de BD y API key segura.

---

## Arquitectura implementada

```
Frontend (JS)
    │
    ├─ guia-book.js    ──┐
    ├─ guia-explorar.js ─┤─→ POST /api/guia/chat  (SSE)
    └─ guia-chat.js    ──┘         │
                                   ├─ build_db_context() → consultas PostGIS reales
                                   ├─ build_system_prompt() → system.md + CONTEXTO_ACTUAL
                                   └─ stream_pibico() → proxy httpx SSE
```

## Decisiones importantes

### docs/astuguia/system.md es el documento maestro
- El backend lo carga con `@lru_cache` y lo inyecta como `system_prompt` en CADA llamada a pibiCo
- Contiene TODO: identidad, reglas, seguridad, info Asturias, lista 78 concejos para tag NAV
- `identidad.md` fue fusionado en `system.md` y eliminado para evitar redundancias y confusión al modelo

### Flujo SSE bridge
- El backend inyecta `event: conv_id\ndata: {id}` cuando recibe un nuevo conversation_id de pibiCo
- El frontend JS lo captura y lo guarda en `sessionStorage(CONV_KEY)`
- La API key de pibiCo nunca sale del servidor

### Fallbacks frontend
- `guia-book.js showResult()`: si la IA no retorna `[NAV:X]`, usa el array FEATURED como fallback
- `guia-explorar.js say_ai()`: si la IA falla, usa el mensaje hardcodeado como fallback
- `say_ai()` cancela streams anteriores con AbortController antes de iniciar uno nuevo
