## 2. Fix `detectCategory` en `guia-chat.js`

### Problema original

Cuando el chatbot recomendaba un municipio, el botón "🗺️ Ir a X" siempre navegaba a `?cat=senderismo` por defecto, independientemente del contenido de la respuesta.

### Cambios realizados

**Fallback por defecto:** `'senderismo'` → `'ocio'`
- Las sugerencias generales sin keywords específicos ahora llevan a la categoría ocio, no a senderismo.

**Keywords añadidos:**
- `ocio`: añadidos `'visitar'`, `'conocer'`, `'ver'`
- `comer`: añadidos `'cenar'`, `'almorzar'`
- `tiendas`: añadido `'donde comprar'`

**Categoría `'comer'` mantenida (no cambiada a `'restaurantes'`):**
- Se intentó cambiar a `'restaurantes'` pero se revirtió porque `'comer'` es el valor canónico en toda la cadena del sistema (BD, API endpoint `CategoriaType`, `explorar.js`, `pages.py`, `guia.py`).

### Lógica de navegación resultante

| Contenido de la respuesta | Categoría destino |
|---|---|
| restaurante, comer, sidra, bar, gastronomía… | `comer` |
| tienda, compras, comercio, donde comprar… | `tiendas` |
| mercado, productos locales, artesanía… | `mercado` |
| monumento, museo, visitar, cultura, arte… | `ocio` |
| senderismo, senda, trekking… | `senderismo` |
| ciclismo, bicicleta, en bici… | `ciclismo` |
| carril bici, ciclocarril… | `carril_bici` |
| senda verde, vía verde… | `sendas_verdes` |
| paseo, caminata, caminar… | `paseos` |
| **sugerencia general (sin keywords)** | `ocio` (fallback) |

## Notas técnicas

- No se requiere reinicio de supervisor (cambio solo en archivo JS estático)
- `detectCategory` analiza el texto completo de la respuesta del bot, no el mensaje del usuario
- La detección usa la función `normalize()` (quita acentos, minúsculas) para comparación robusta
- El orden de `CATEGORY_KEYWORDS` importa: las rutas específicas tienen prioridad sobre categorías genéricas
