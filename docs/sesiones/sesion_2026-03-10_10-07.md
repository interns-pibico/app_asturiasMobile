## 1. Revisión categoría `paseos`

### Problema detectado
La query Overpass usaba `way[highway=pedestrian][name]` — devolvía 1566 registros con callejuelas genéricas (longitud media 97m, nombres como "Calle Severo Ochoa", "Rotonda del Piles").

### Solución aplicada
Modificado `scripts/import_rutas_osm.py` — nueva query `paseos`:
```python
(
  way[leisure=promenade](area.asturias);
  way[highway=pedestrian][name~"paseo|rambla|malecón|esplanad|alameda|bulevar|ribera|litoral|muro|playa",i](area.asturias);
  relation[type=route][route~"foot|walking"][name~"paseo|rambla|litoral|ribera|muro",i](area.asturias);
);
```

### Resultado
| | Antes | Después |
|---|---|---|
| Total registros | 1566 | 105 |
| Calidad | Callejuelas genéricas | Paseos reales |

Gijón: 502 → 45 registros. Todos paseos reales: "Paseo del Muro" (3.9km), "Paseo del Muelle", "Alameda de Manuel Preciado"...

## 3. Filtro longitud mínima `carril_bici`

Aplicado filtro de 50m para eliminar micro-fragmentos de segmentación OSM.

**BD:** `DELETE FROM rutas_carril_bici WHERE ST_Length(geom::geography) < 50;` → 281 eliminados, 513 restantes.

**Script:** Añadido filtro en `import_rutas_osm.py` para futuras re-importaciones:
```python
if tipo == "carril_bici" and distancia_m and distancia_m < 50:
    skipped += 1
    continue
```

## 4. Enriquecimiento de elevación — `paseos`

Los 105 paseos nuevos necesitaban datos de elevación.

### Bug corregido en `enrich_elevacion.py`
`get_elevations_opentopodata()` usaba POST con formato Open-Elevation (`{"locations": [...]}`) pero OpenTopoData espera GET con `?locations=lat,lng|lat,lng`.

**Fix:** Cambiado a GET con pipe-separated locations:
```python
locs_str = "|".join(f"{p['latitude']},{p['longitude']}" for p in chunk)
url = f"{OPENTOPODATA_URL}?locations={locs_str}"
```
